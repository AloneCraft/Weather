# 画面構成と画面遷移

MVVM(CommunityToolkit.Mvvm)+ MAUI Shell。ViewModel は `Weather.Presentation`(net10.0)に置き、MAUI に依存しない。View(XAML)と MAUI 固有の実装は `Weather.App` に置く。

## 決定事項

| 論点 | 決定 | 根拠 |
|---|---|---|
| グラフ | `Weather.Rendering.Charts` の自前描画(Rendering.md) | SkiaSharp 4 と既製ライブラリ(3.119 依存)の衝突回避、見た目の統一 |
| トップ画面 | **Windy 型の地図**(2026-10-04 にユーザーの要望で変更)。地図の全面に風の粒子・降水・気温・雲と気圧を描き、時間軸で動かす。地点をタップすると吹き出し → 予報シート → 空のシーンの詳細 | 文字中心の一般的な天気アプリではなく、地図アプリとして見せる |
| 地図の描画 | `Weather.Rendering.Map` の自前描画(Web メルカトル)。背景はオフラインのベクター地図 | オフライン動作、キー不要、気象庁のタイルと重ねられる |
| UI 言語 | MVP は日本語。文字列は最初から resx に置き、英語は後で追加する | 利用者は日本語話者。世界の地点名は GeoNames の日本語名・英語名を使う |
| 単位の既定 | 端末の地域が米国なら °F / mph / inch、それ以外は °C / m/s / mm。設定で変更可 | 地域の慣習に合わせる |
| テーマ | 地図の画面は暗い基図の上に濃い半透明の部品を重ねる。詳細画面の文字の色はシーンの明るさに追従させる(VM が背景が暗いかを公開する) | 地図の色の層を主役にする。詳細は背景がシーン描画のため、固定のライト/ダークでは読みにくい |

## 画面遷移(Shell ルート)

```
//main(ルート。地図)
 ├─ push  placedetail                          (予報シートの地点。空のシーン)
 ├─ push  hourly?place={placeId}
 ├─ push  daily?place={placeId}&date={yyyy-MM-dd}
 ├─ push  alerts?place={placeId}
 │    └─ push alert?place={placeId}&id={alertId}
 ├─ push  history?place={placeId}              (Phase 2)
 ├─ modal search                               (選んだ地点は地図に戻って予報シートを開く。MapFocusService)
 ├─ push  places
 ├─ push  settings
 │    └─ push about
```

ナビゲーションは Presentation の `INavigator`(`GoToAsync(route, parameters)`)経由で行う。VM が Shell を直接触らない。

Presentation に定義する抽象(App が実装):

| 抽象 | 内容 |

## MAUI 固有の注意点

- **コンパイル済みバインディング**: すべての XAML で `x:DataType` を指定する。性能面と、トリミング時にバインディングが壊れないための対策。.NET 9 以降はコンパイルされないバインディングに警告が出る。
- **Shell の引数**: `IQueryAttributable` は MAUI の型なので VM に実装しない。Presentation に `INavigationAware.OnNavigatedToAsync(IReadOnlyDictionary<string,string>)` を定義し、App のページ基底クラスから呼ぶ。
- **スレッド**: VM のメソッドでは `ConfigureAwait(false)` を使わない(UI スレッドに戻って PropertyChanged を発火させるため)。Providers・Infrastructure では `ConfigureAwait(false)` を使う。
- **ソース生成**: `[ObservableProperty]` は部分プロパティ(partial property)の形で書き、`[RelayCommand]` は CancellationToken 対応の非同期コマンドにする。
- **ライフサイクル**: `Window.Stopped` で描画ループを止め、自動更新も止める。`Window.Resumed` で必要なら更新する。
- **レイアウト**: 地図・シーンのキャンバスを Grid の最背面に置き、上に半透明の部品を重ねる。iOS はセーフエリアを考慮する。
- **地図の操作**: MAUI のジェスチャー(パン・ピンチ・タップ・ダブルタップ)を地図のビューに付け、座標は端末の密度を掛けて描画の画素に直す。ピン(吹き出しの形)はタップの判定を地点より優先する。
- **描画ホスト**: 地図は風の粒子があるときだけ連続描画し、それ以外は操作・データの更新のたびに 1 回描く(電池の消費を抑える)。
- **位置情報の権限**: 初回は説明を表示してから要求する。拒否された場合は検索で使えるようにする。

## 出典の表示ルール

- 予報・警報・観測を表示する各カードの下部に、短い出典を出す(例:「気象庁 05:00 発表」「MET Norway 06:30 更新(アプリで集計)」)。
- タップすると出典の詳細(機関名、プロダクト名、発表時刻、取得時刻、ライセンス、出典 URL、加工の有無)を表示する。
- 気象庁: 「出典:気象庁ホームページ」と対応ページの URL を必ず表示する。`Processing` に加工がある場合は、その旨を併記する。
- MET Norway: CC BY 4.0 / NLOD 2.0 のクレジットとライセンスへのリンク。日別はアプリで集計した旨を表示する。
- `IsStale`: 「最終取得 hh:mm(オフライン)」を表示する。
- 地図: 画面下に出典の帯を常に表示し、表示中のデータ源(例:「NOAA GFS 0.5° 09:00 初期値 | 気象庁 17:15 発表」「気象庁 17:40 観測」)を並べる。タップで「データと出典」へ。GFS は数値予報モデルの計算結果であることを製品名と「初期値」で示す。

## 状態の表示

| 状態 | 表示 |
|---|---|
| 読み込み中 | 前回のデータがあれば表示したまま、控えめな表示を出す |
| 古いキャッシュ | 取得時刻と「オフライン」を表示 |
| 補助プロダクト欠落(Issues) | 該当の欄に「取得できませんでした」 |
| 日本の対象外 | 「この地点は気象庁の予報区域外のため表示できません」。シーンは空のみ |
| 最寄り区域で表示 | 「最寄りの予報区域:〇〇市」 |
| 位置情報が拒否された | 検索への導線 |
| 警報非対応の地域 | 「この地域の警報情報は提供されていません」(「警報なし」と区別) |
| 地図: 日本周辺に気象庁のデータがない時刻 | 凡例の下に「日本周辺: この時刻の気象庁のデータはありません」。日本周辺は基図のまま |
| 地図: 気象庁の予報期間外 | 「日本周辺: 気象庁の予報期間外のため表示しません」と斜線(GFS で埋めない) |
| 地図: 一部のデータを取得できない | 凡例の下に「GFS を取得できませんでした」等(取れた部分は表示する) |

## ウィジェットと警報の通知(Phase 3)

| 項目 | 決定 |
|---|---|
| 背景で取得する地点 | お気に入りの先頭から最大 5 地点。気象庁・NWS の地点だけ(MET は規約で禁止、日本の対象外地点はデータがない) |
| ウィジェットの地点 | 現在地を除いた先頭の地点(お気に入りの先頭)。背景位置情報は使わない |
| ウィジェットの内容 | 地点名・気温・天気(日本は気象庁の天気文)・最高 / 最低・降水確率・発表中の警報の名称・出典表記・発表時刻・取得時刻。文字列は Presentation で書式済みにし、Android / iOS(Swift)は表示するだけ(WidgetSnapshot の JSON) |
| MET の地点のウィジェット | アプリの使用中に取得した内容を表示し、「アプリを開いたときに更新」と明記する |
| 通知する警報 | 警報以上(気象庁の警報・危険警報・特別警報、NWS の Warning 以上)。注意報・Watch は通知しない |
| 通知の文面 | 機関の名称・見出しをそのまま使い、区域・発表時刻・出典表記を付ける。アプリ独自の危険度の判断や表現を加えない(気象業務法第 23 条) |
| 再通知 | 同じ警報(機関・種類・区域が同じ)は再通知しない。解除されたら記録から外し、再び発表されたら通知する。NWS は更新のたびに ID が変わるため ID では判定しない |
| 実行間隔 | Android は WorkManager の 30 分周期(ネットワーク接続時)、iOS は BGAppRefreshTask(早くても 30 分後。実行は OS 次第で保証されない)。通知もウィジェットもなければ何も取得しない |
| iOS のウィジェット | WidgetKit 拡張(Swift)を任意で同梱する(`-p:IncludeWidgetExtension=true`)。App Group を有効にしたプロビジョニングが必要。WidgetCenter は Swift の API のため、拡張側が 30 分ごとにファイルを読み直す |

## アクセシビリティ

- シーンは装飾として扱い、代わりに天気の要約を `SemanticProperties.Description` に設定する。
- 文字のコントラストは、シーンの明るさに応じて自動で調整する。カード(時間別・日別・出典)は常に濃い半透明の背景に白い文字を載せる(行のテンプレートは地点の背景に依存できず、画面下部は地形で暗いため。エミュレーターでの確認で、明るい曇り空の背景でカード内の文字と出典が読めなかったことから決定)。
- 「視差効果を減らす」が有効なら、静止または低速のシーンにし、稲光の点滅を抑える。地図の風は粒子を止め、静止した矢印にする。
- 地図の値は吹き出し・予報シートの文字で読み上げられる(地図の画像そのものは読み上げない)。
